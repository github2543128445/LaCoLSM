TimberSaw文件格式
===================

    <文件开始>
    [数据块1]
    [数据块2]
    ...
    [数据块N]
    [元数据块1]
    ...
    [元数据块K]
    [元数据索引块]
    [索引块]
    [页脚]        (固定大小；从file_size - sizeof(Footer)开始)
    <文件结束>

文件包含内部指针。每个这样的指针被称为BlockHandle(块句柄)，包含以下信息：

    offset:   varint64
    size:     varint64

关于varint64格式的说明，请参见[varints](https://developers.google.com/protocol-buffers/docs/encoding#varints)。

1. 文件中的键/值对序列按排序顺序存储，并分区为一系列数据块。这些块在文件开始处一个接一个地排列。
每个数据块根据`block_builder.cc`中的代码格式化，然后可选地进行压缩。

2. 在数据块之后，我们存储一组元数据块。支持的元数据块类型在下面描述。将来可能会添加更多元数据块类型。
每个元数据块同样使用`block_builder.cc`格式化，然后可选地进行压缩。

3. "元数据索引"块。它为每个其他元数据块包含一个条目，其中键是元数据块的名称，
值是指向该元数据块的BlockHandle。

4. "索引"块。这个块为每个数据块包含一个条目，其中键是一个字符串，大于等于该数据块中的最后一个键，
且小于后续数据块中的第一个键。值是该数据块的BlockHandle。

5. 在文件的最末尾是一个固定长度的页脚，其中包含元数据索引和索引块的BlockHandle以及一个魔数。

        metaindex_handle: char[p];     // 元数据索引的块句柄
        index_handle:     char[q];     // 索引的块句柄
        padding:          char[40-p-q];// 补零以达到固定长度
                                      // (40==2*BlockHandle::kMaxEncodedLength)
        magic:            fixed64;     // == 0xdb4775248b80fb57 (小端序)

## "filter"元数据块

如果在打开数据库时指定了`FilterPolicy`，则在每个表中存储一个过滤器块。"元数据索引"块包含一个条目，
将`filter.<N>`映射到过滤器块的BlockHandle，其中`<N>`是过滤策略的`Name()`方法返回的字符串。

过滤器块存储一系列过滤器，其中过滤器i包含对所有存储在文件偏移量落在以下范围内的块中的键
调用`FilterPolicy::CreateFilter()`的输出：

    [ i*base ... (i+1)*base-1 ]

目前，"base"是2KB。例如，如果块X和Y的起始位置在范围`[ 0KB .. 2KB-1 ]`内，
X和Y中的所有键都将通过调用`FilterPolicy::CreateFilter()`转换为过滤器，
生成的过滤器将作为过滤器块中的第一个过滤器存储。

过滤器块的格式如下：

    [过滤器0]
    [过滤器1]
    [过滤器2]
    ...
    [过滤器N-1]

    [过滤器0的偏移量]                  : 4字节
    [过滤器1的偏移量]                  : 4字节
    [过滤器2的偏移量]                  : 4字节
    ...
    [过滤器N-1的偏移量]                : 4字节

    [偏移量数组开始的偏移量]            : 4字节
    lg(base)                          : 1字节

过滤器块末尾的偏移量数组允许从数据块偏移量到相应过滤器的高效映射。

## "stats"元数据块

这个元数据块包含一组统计信息。键是统计信息的名称。值包含统计数据。
